# Evaluation protocol

How each stage is validated, what counts as a pass, and what cannot be claimed. The clip has no
tracking, identity, team or event ground truth, so most checks are internal. Results are in
`docs/evaluation.md`; this file fixes the *method* so a re-run or a new clip is comparable.

## 1. Rules

1. A metric is reported only where its ground truth exists. HOTA, IDF1, team accuracy and
   positional error against real positions need labels; none exist for this clip, so none is
   reported. Where only an internal check is possible it is named as one.
2. Pass thresholds are fixed before the run (below), seeds are fixed, configuration is logged
   (`reconstruction_summary.json` stores the settings used).
3. Baselines stay recoverable: `baseline-v0.1` tag and `artifacts/<clip>/baseline_v0.1/`.
4. Every number in the docs is regenerated by a command in §6.

## 2. Calibration

- In-sample: keyframe fit residuals at the clicked landmarks (RMS and max, metres).
- Out-of-sample: homography propagated from keyframe A, evaluated at keyframe B's landmarks and a
  grid of image probe points (median and max, metres).
- Coverage: share of wide-view frames per `calibration_status`.
- **Pass:** drift within `max_keyframe_dt_s` stays within a few metres; frames beyond it are rejected,
  never kept with a guess.
- **Cannot claim:** error against a surveyed pitch. The pitch is a 105 × 68 m reference.

## 3. Team classification

- Internal stability: per track, share of torso crops whose nearest kit cluster equals the track's
  label (`agreement`). Tracks with agreement < 0.8 or fewer than 5 crops are `uncertain`.
- Label stability across the run: labels are unchanged by the confidence step (diffed against the
  previous `track_teams.csv`).
- Referees, goalkeepers and unclustered tracks are `other`, kept out of both teams.
- **Cannot claim:** team accuracy. A hand-labelled sample is the required next step; with it,
  report accuracy per class and the confusion matrix.

## 4. Reconstruction: masking evaluation

Question: given a track the system observed continuously, how well does each method recover a
hidden window of it?

- **Windows.** Consecutive observed runs per identity and shot. Hide `L` samples for
  `L ∈ {0.6, 1, 2, 4, 8} s`, plus one guard sample on each side (the truth `x_s` is a rolling
  median and would leak the hidden values otherwise). Keep at least 5 clean samples on each side.
  Windows within a run do not overlap.
- **Methods.** `hold`, `linear`, `cv`, `kalman` (history only) and `rts` (Kalman + RTS smoother).
  History-only methods answer "predict ahead", `linear` and `rts` answer "fill a bracketed gap".
- **Scores.** MAE with a 95 % bootstrap interval resampled over windows, RMSE, median, p90, mean
  reported sigma, and calibration of that sigma: share of samples with error ≤ 2.448 σ (95 % of an
  isotropic 2-D Gaussian).
- **Pass (set before the run):** the shipped defaults must be the lowest-MAE method of their kind at
  the gap lengths where they are used, and the 95 % coverage of the shipped uncertainty (`rts`) must
  be ≥ 0.90.
- **Cannot claim:** errors against real pitch positions. The truth is the pipeline's own smoothed
  projection, so calibration drift and jitter are inside it (that error is measured separately,
  docs/evaluation.md §10: about 4 m on propagated frames). Only short-range relative accuracy of
  the motion model is measured.
- **Known bias:** the `predict = cv` default was selected on this same masking data.

## 5. Identity and tracking

No identity ground truth exists, so HOTA and IDF1 are not reported. What can be checked without it:

- Track counts and fragment lengths before and after any linking step.
- Linking must preserve ambiguity: a candidate pair with a second plausible partner is left unlinked.
- A self-supervised check is possible (split a long track in two, hide the join, see whether a linker
  rejoins it); it measures the linker's recall on easy cases only.

No linker is shipped; see `docs/audit_and_findings.md` §4.

## 6. Reproducible commands

```bash
python -m pytest tests -q                            # 42 tests
python -m football_cv.pipeline reconstruct           # player_states.parquet, gaps.parquet, summary json
python -m football_cv.pipeline reconstruction_eval   # masking_eval.csv
python -m football_cv.pipeline visualize             # state animations per candidate sequence
```

## 7. Failure analysis checklist

For every run, read the rows with the largest masking error and the gaps left unfilled, and record
which of these explains them: calibration drift at the image edge, a fast direction change inside
the gap, a tracker break mistaken for occlusion, the player leaving the frame, or a rejected jump.
The current clip's analysis is in `docs/evaluation.md` §9.
